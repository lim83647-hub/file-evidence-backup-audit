# 文件铁证：逐文件备份核验与安全清理法

> 一套用于核查“本机文件是否真的完整保存在云盘”的可复用流程。核心原则：**文件名和大小相同只是候选匹配；下载后的字节内容通过密码学哈希比对，才算内容核验通过。**

## 1. 先说清楚核验范围

记录本机根目录、云端备份根目录、核验时间、要排除的文件类别，以及是否需要保留目录结构、符号链接和扩展属性。结论只能覆盖这个范围和核验当时的文件版本，不能自动扩展到整台电脑或以后新增的文件。

建议将结果分成三个不同层级：

| 层级 | 能说明什么 | 不能说明什么 |
| --- | --- | --- |
| 路径存在 | 云端有一个候选文件 | 不能证明大小或内容相同 |
| 路径与大小一致 | 云端文件可能是同一版本 | 不能证明内容相同 |
| 下载后 SHA-256 一致 | 核验时两边的文件字节内容一致 | 不能证明路径、链接、扩展属性也相同，或以后不会变化 |

## 2. 建立两边的清单

递归遍历本机和云端，分别记录文件的相对路径、类型、字节数；本机还记录修改时间、inode 等用于识别核验期间变化的信息，云端记录稳定的文件 ID。目录、普通文件、符号链接要分开统计，不要把链接当普通文件或递归跟随链接。

以相对路径匹配为首选；如果云盘会去掉文件名末尾空格、规范化 Unicode 或改变某些字符，只能在**本机和云端都唯一匹配**时标记为“名称规范化的候选项”。不能把不同文件夹名中的 `+` 和空格一概视为相同。记录原始路径与云端实际路径，不能悄悄合并。

清单至少区分：完全同路径、唯一名称规范化、大小不同、本机独有、云端独有、符号链接、空目录与特殊文件。云端独有文件可能是先前已从电脑移走的备份，不能仅凭“云端多了”判为错误。

## 3. 对每个普通文件做内容核验

对于路径已唯一匹配且大小相同的文件：

1. 记录本机文件核验前的大小、修改时间和 inode。
2. 分块读取本机文件的**全部字节**，计算 SHA-256。
3. 用云端文件 ID 获取下载链接，下载云端文件；边下载边计算 SHA-256，并累计实际下载字节数。不能只信云端接口的 `md5` 或仅下载开头一小段。
4. 通过条件是：`下载字节数 == 本机字节数` 且 `云端 SHA-256 == 本机 SHA-256`。
5. 再检查本机文件大小、修改时间和 inode 未变化；必要时重新计算本机 SHA-256。若文件在核验过程中变化，这次结果作废。

伪代码：

```text
before = local_stat(path)
local_digest = SHA256(read_all_bytes(path))
downloaded_bytes, cloud_digest = SHA256(stream_download(cloud_file_id))
after = local_stat(path)

verified = (
    before == after
    and downloaded_bytes == before.size
    and cloud_digest == local_digest
)
```

这里是以 SHA-256 比较完整字节内容，而不是逐字节同步扫描两边。对于备份核验，这提供了强力的内容一致性证据；它仍不检查图片是否科学上正确、文档能否被应用正常打开，或文件所依赖的软件环境是否完整。

## 4. 记录证据，重试失败，不能把错误算通过

为每个文件保存相对路径、本机大小/修改时间/inode、云端文件 ID 和实际路径、SHA-256、核验时间、通过或失败状态。记录应可追加、可续跑；不要在日志中保存访问令牌或下载链接。

网络超时、代理错误、TLS 错误或云端限流应标记为“未完成”，稍后重试。SHA-256 不一致应重新下载复核，并确认本机文件没有在核验时改变；持续不一致才作为真正的内容异常处理。**失败记录不能因同名同大小而自动转成通过。**

## 5. 单独审计结构与附属内容

文件内容通过，不代表整个文件夹原样复制。另列出：

- 云盘改名或规范化后的路径；
- 符号链接及其目标（云盘可能不保存链接本身）；
- 空目录和只含被排除文件的目录；
- `.DS_Store`、Office 锁文件、临时文件、缓存等；
- 可能含登录信息的自动化痕迹与密钥文件；
- macOS 扩展属性、资源分叉和其他元数据。

对科研项目，原始图像、实验数据、分析表格、论文文件、代码与 Git 历史应作为实质内容核验；不要把 `.git` 简单归入可丢弃缓存。含密钥的文件不可为求“齐全”而明文上传。

## 6. 删除前再设一道闸门

若核验后要移走本机文件，**先固定待处理目录清单**，不要让后台新增的已核验目录自动进入删除范围。对清单内每个目录重新遍历，确认没有新增、改变或未核验文件，且没有需要保留却未备份的链接或元数据。再在线查询对应云端文件 ID、实际路径和大小仍存在；查询失败时跳过该目录。

只移动明确授权且通过最终检查的精确路径。优先移入系统废纸篓，记录成功、跳过和失败，核对原位置已不存在；不要自动清空废纸篓。**移入废纸篓不等于立即释放磁盘空间。**若云盘将成为唯一长期副本，应考虑再留一份独立备份，并抽查能否从云盘恢复关键文件。

## 7. 最终报告应怎么写

至少写清：核验范围和时间、普通文件总数、同路径内容通过数、名称规范化但内容通过数、未完成与真正不一致数、排除项、符号链接/目录/元数据差异，以及是否发生过移动或永久删除。推荐明确写成：

> “在本次核验范围与时间点内，所列普通文件已逐个下载并通过 SHA-256 内容比对。此结论不涵盖排除项、链接与元数据，也不保证核验后的新增或修改文件已备份。”

不要把“绝大多数通过”写成“所有文件完全一致”，也不要把“普通文件内容一致”写成“整台电脑可以安全删除”。

## 最简检查表

- [ ] 范围、映射和排除项已写明
- [ ] 本机与云端完整清单已建立
- [ ] 名称规范化匹配是唯一的，歧义已单列
- [ ] 每个候选文件已完整下载并比对字节数与 SHA-256
- [ ] 本机核验前后未变化
- [ ] 网络失败和哈希不一致已重试或明确列为未完成
- [ ] 链接、空目录、隐藏文件和元数据差异已单列
- [ ] 删除范围已冻结并再次在线确认
- [ ] 只移入废纸篓，未自动永久清空

这是一套核验方法，不是对任何特定云盘或电脑“永远安全”的承诺。重要数据仍应遵循多副本、不同介质或不同服务保存的原则。
